# 本次修复与新增功能

## 启动、开屏动画与自动换行

启动慢的主要额外工作包括：提前解析所有系统字体、为隐藏的设置与单词本面板生成字体图形，以及音乐关闭时仍加载整首音频。现在仅解析选中的字体，首次打开设置或单词本时才构建面板，开启音乐后再加载音频，主题文件只在内容变化时写入。

原先约 1.35 秒的程序绘制开屏省略了参考视频的完整节奏，字形和背景细节也有明显差距。现在首页名称改为 **cybertranslator**，按参考的完整约 **11 秒**重做：红黑背景由去除旧字标的视频播放，新的透明锐角黄色字标通过着色器呈现青色色差、横向切片和故障闪动。背景转换为 640×360 无声 Theora，由 Godot 内置解码，便携包无需额外播放器。

此前开屏属于 Godot 场景，要等引擎、扩展与自动加载脚本初始化后才能出现，因此无法覆盖约一秒的启动空白。现在便携入口 **GriddyTranslate.exe** 先使用 Windows 内置 WIC 播放 Full HD 动画帧，再启动 Godot；画布在它后方加载，原生开屏直到画布实际绘制完成才允许退场。引擎不再重复加载第二份开屏。直接运行 runtime.exe 时仍保留内置 Godot 开屏作为备用。

**完整 logo 实际画出至少半秒，且画布首帧完成后，才接受按键或点击跳过**，提前按键不会排队触发。跳过和自然播放结束都经过约 **0.45 秒切片退场与淡出**，恢复原画布焦点；重复按键不会截断退场。设置关闭动画后不加载开屏资源。便携包不依赖 Python、Godot 编辑器或外部播放器。测试覆盖引擎内置备用流程及真实 Windows 启动入口的早期显示、加载握手、跳过门槛和焦点恢复。

自动换行使用编辑器原生软换行，不改动原文中的真实换行，复制、撤销、翻译和完整短语例句查询均保留原始文本。设置中的“每行长度”按英文等宽字符的显示宽度计算，范围 10–120，默认 40；中文通常占约两个字符宽，英文会优先在单词间换行。原文和译文都适用，镜头按显示行而不是整段长文本缩放，例句放在全部显示行下方。

本次为本地预览版。GitHub 源码同步和便携包发布均等待用户确认，已取代之前的自动发布规则。

## 文字高亮、主题掉帧与菜单晃动

Rose Pine Moon、Rose Pine 等原版主题将重复单词的高亮背景设为与正文相同的不透明浅色，叠加选区后会把字形混入整块背景。部分浅色主题的当前行与选区叠加也会降低对比度。现在明确设置选中文字颜色，并按叠加顺序检查当前行、选区及重复词背景；只有对比度不足时才降低背景透明度，保留主题色相、字体和泛光。附带主题均检查实际渲染的选中词与重复词；单词本编辑框也应用选区配色保护。

原主题预览每次发出设置重建信号，重新创建全部设置和字体选项。之后各控件每添加一种颜色或样式，还会触发原生下拉菜单重新计算布局，包括隐藏的长字体列表。现在主题预览只更新配色，复用控件、字体和菜单行，并批量提交同一控件的样式更新；隐藏的设置与单词本在打开时更新。同一主题的悬停与确认不重复加载。连续主题预览检查记录 CPU 耗时和实际帧间隔，避免仅用主题加载时间判断掉帧。

下拉菜单先前固定在屏幕上，而按钮所在画布继续浮动，产生相对运动。现在在最终绘制前读取按钮的实际位置，菜单以同一帧、同一位移跟随，不对坐标四舍五入；只在打开和窗口缩放时计算大小与方向，避免布局反复变化。Ctrl+T 主题按钮缩为紧凑宽度并向左移，给输入区留出间隔。拖动滑块时仍只固定滑块和数值。

快速主题预览会替换“主题关闭泛光”等提示。Godot 4.2 中，旧提示的异步布局任务可能在等待下一帧时保留字体和画布变换，退出时留下绘制资源。现在将测量阶段放在同步函数中，资源在进入等待前释放；主题渲染检查也验证正常退出。

## 通知样式、动画与删除同步

左上角通知改为无外框的直角卡片与左侧色条；从当前主题取背景、文字和强调色。通知滑入淡入，停留后滑出淡出；新通知平滑替换旧通知，文字自动换行，所有元素始终忽略鼠标输入。

之前删除单词本词条只更新本地 JSON，Obsidian 笔记按旧设计保留。现在删除会产生持久记录，后台按固定 ID 查找对应笔记并移入系统回收站；失败不清除记录，也不连续重试，可以用立即同步重试。新增正在写入时删除会排到新增之后，避免笔记重新出现。只删除有效管理笔记，回收的完整文件保留手写内容。旧版本完整上一版备份若能确认最近一次只删除了一个词，也会将这次删除带入同步；不会按本地缺失批量清扫其他笔记。

## 单词本与 Obsidian

新增 Ctrl + D 收藏原文选中的单词或完整短语；没有选区时使用完整输入，长句需先选词。Ctrl + B 在原画布中呼出单词本，保留字体、泛光、滑入与聚焦；支持搜索、Enter 详情、Ctrl + E 编辑译文/标签/笔记、Ctrl + Enter 保存、原词与译文读音。重复收藏按单词及语言方向合并，英语可在后台补充有道真实词典音标和例句。Delete 需再次确认，并按同步设置处理 Obsidian 笔记。

现有设置增加 Obsidian 保管库、库内同步文件夹、自动同步开关和立即同步。首次配置优先选择 Obsidian 注册的当前打开库；本机发现的是 iCloud 中的 Eng，路径来自 Obsidian 配置，未硬编码。默认写入库内 `GriddyTranslate/单词本`，每词一个 Markdown 文件；Ctrl + Shift + O 可打开所选词条。文件同步与改名查找在工作线程执行，不占用画布动画和输入。

软件更新限定在固定 ID 对应的管理内容块及软件 frontmatter 字段，保留用户标题、块外手写文字、未知字段和 Obsidian 用户标签。本地编辑的笔记写入“单词本笔记”，Obsidian 末尾“我的笔记”由用户维护；当前为从本地单词本写入 Markdown 的联动。配置文件夹及其子目录内改名/移动后仍按 ID 定位；同名普通文件、ID 副本、损坏管理标记和并发编辑不会被覆盖。

Windows 下 Godot 的普通覆盖重命名会先删除旧目标，因此同步改用原子 File.Replace，并在提交前核对原始字节 SHA256。路径校验拒绝越界、符号链接和 junction；iCloud 的 cloud reparse tag 属于占位机制，允许使用，避免把正常 iCloud 文件误判为库外重定向。内容不变时跳过替换，减少 iCloud 文件变更。

个人词条保存在 `%APPDATA%\Godot\app_userdata\GriddyTranslate\wordbook.json`，保留 `.bak` 上一版及可能的 `.rollback` 中断恢复文件。主文件缺失可恢复完整副本；损坏文件不会被空库覆盖。便携 ZIP 仍只分发程序，换电脑需另外迁移个人单词本，并选择新电脑的保管库路径。详细步骤见使用说明。

## 翻译与读音响应

旧自动翻译在停止输入后固定等待 1.2 秒；旧请求还没完成时，下一次翻译会排队，并再次等待自动翻译计时器。现在停止输入 0.5 秒后请求，手动 Ctrl + Enter 立即请求。修改原文、切换来源或语言会取消旧请求；独立请求标识避免取消后的旧结果覆盖新译文或干扰新请求的状态。

旧版给有道也使用 MyMemory 的 450 字节分段，长中文会拆成许多串行请求。有道现改用 POST、每段最多 1000 个 UTF-16 单位；MyMemory 保留自己的 450 字节限制。最多并行两段，结果按原顺序合并。同一来源、语言、文本的重复请求合并等待，译文继续使用有界内存缓存。

旧句子读音有时先尝试词典，收到 HTTP 500 后才获取语音签名，再下载音频。现在只对符合条件的单词尝试词典，句子直接使用语音服务。有道翻译返回的原文与译文读音地址分别按完整文本和语言短期缓存，Ctrl + P / Ctrl + O 可以省去再次获取签名的请求；过期地址会清除并重新获取。已经播放过的相同文本使用内存音频缓存。软件不会在输入时预先下载读音。

## 设置滑块精准调整

设置面板聚焦时，相机的周期性浮动仍在每帧更新；原有轨道只有 76 个画布单位宽，动画速度的 25%–300% 范围被压到很短的距离，几像素的移动就会带来明显误差。滑入已经完成时，相机的一秒聚焦动画也可能仍未结束。

现在按住滑块时，仅固定这个轨道与数值的屏幕位置和大小，通过抵消该控件受到的镜头变换来保持精度；镜头、其他文字和控件继续运动。松手后滑块在 0.12 秒内平滑回到本行，不修改“屏幕晃动”偏好。轨道加长至 132 个画布单位，并保留原有字体、泛光与行结构。滑入期间暂不接收滑块鼠标操作，Esc 关闭面板、设置重建或窗口失焦都会恢复控件原本的位置。点击滑块后，左右方向键可逐单位细调。

## 原文与译文读音

Ctrl + P 播放原文，Ctrl + O 播放译文；原有语言选择改用 Ctrl + L。播放按下快捷键时的文本和语言快照，译文使用实际翻译结果的目标语言，保留原文与下一行译文的显示模式也不会让两段一起被读取。有道词典读音适用于单词，完整句子使用有道体验接口返回的签名语音地址；较长文本会按需分段播放。重复操作会取消旧请求，过期响应不能抢占新播放。

## 新版选择菜单

旧版使用 Godot 原生 PopupMenu，在世界画布缩放、镜头移动和窗口缩放共同存在时，展开列表的定位与文字缩放容易和按钮不一致；灰色默认样式也与主题画布脱节。现在展开列表在屏幕画布中按真实窗口像素绘制，使用 MSDF 字体，展开时固定菜单及按钮，窗口缩放后重新对齐。列表跟随当前主题配色，采用细边框、圆角、高亮与选中状态，去掉原生圆点；长列表支持滚动、方向键和边界适配。Esc 优先收起展开菜单，快捷键仍可切换面板。

原版场景、脚本与用户提供的截图保留在 `src/Original/SelectionMenuBeforeRedesign`，该目录不参与应用导入和运行。

另外修复了通知框的透明全屏区域拦截点击的问题：切换某些主题会出现提示，旧通知根控件虽然只有角落显示文字，却覆盖整个窗口并阻挡设置点击。现在通知及背景、文字均让鼠标事件穿透，提示存在时仍能操作下拉菜单和滑块。

## 例句范围、最小缩放与语言列表

- 删除“从句子/短语里挑出两个关键词”的回退逻辑。现在只有一次完整查询；换用另一词典时也保持相同完整输入。
- 有道结果必须包含与完整查询一致的词典词条，单纯的双语句子搜索结果不构成词条。每条例句还必须包含完整短语或独立单词，避免只匹配短语中的一个词。
- 长句、段落、带句子标点的输入不触发例句；短语未收录时不显示无关例句。主翻译不受影响。
- 顶部灰色空白来自原背景矩形在世界坐标中只有固定大小，镜头缩到 50% 后看到了矩形外部。现在背景位于独立屏幕画布，始终铺满窗口并跟随主题颜色。
- 语言列表原先把镜头对准列表左上角，列表从屏幕中心向下展开，底部被截断。现在用完整列表的中心与实际宽高计算镜头焦点和缩放，保留原有滑入、淡入及方向键选择方式。

## 例句为什么只对少量词有效

旧版只读取 `ec.word.trs.sentence` 中的 `en/zh` 字段，忽略了有道常用的 `blng_sents_part.sentence-pair`。实际查询 `manipulate` 时，有道返回了三条双语例句，例如：

> The technology uses a pen to manipulate a computer.
> 这项技术使用笔来操作计算机。

有例句却不显示，是软件解析字段不完整，并非这个词被禁用。现在优先读取有道双语例句，同时兼容词典内嵌例句、数组和单对象结构，并清理高亮 HTML。没有双语例句时尝试 Free Dictionary / Wiktionary 的真实英文例句，由当前选中的翻译服务翻译。服务没有收录的词仍可能没有例句；软件不会编造例句。

## 例句抖动

旧版每帧用镜头变换的逆矩阵把例句固定回屏幕，正文却跟随镜头。两种坐标处理同时发生，产生不协调的相对移动；随机乱码的字宽也会反复改变换行。现在例句与正文共用镜头，位置和换行按最终例句确定，乱码在固定字位中变化。

## VHS / CRT 的白屏

截图里的大面积白光是过曝错误。继承的 Shader 默认亮度为 `6`，又叠加噪声和原版 HDR 泛光，把颜色推向白色。此外，覆盖层后半段错误地使用了大矩形的局部 UV，导致扫描线与边缘处理不符合屏幕坐标。

现在亮度为 `1.08`、噪声强度降低，并统一使用屏幕坐标。正常效果是老电视的扫描线、轻微 RGB 错位、滚动噪点、曲面边缘和暗角，文字应该保持可读。Sunlight 与 VHS/CRT 一次只开启一种。

## Caret blink interval 是什么

Caret 是输入文字时的竖线或方块光标。间隔决定光标多久切换一次“显示/隐藏”，单位是秒。`0.6` 表示显示约 0.6 秒、隐藏约 0.6 秒，一次完整明暗周期约 1.2 秒。越小闪得越快；关闭“光标闪烁”后这个间隔不再生效。它不控制文字动画、翻译速度或设置动画。

按 **Ctrl + ,** 打开原有设置面板：

## 独立运行与保存位置

固定项目目录：**D:\Documents\GriddyTranslate**。

便携包：`packages\GriddyTranslate-Windows.zip`。把整个 ZIP 解压到任意可写目录后，双击里面的 **GriddyTranslate.exe**；无需安装 GriddyCode、Godot、Python 或 Codex。

入口是原生 Windows 启动器，自动给翻译器进程设置 RTSS Vulkan 图层兼容参数。运行时、资源包和 Lua DLL 全部随 ZIP 提供，路径均相对于解压目录。翻译器不使用单实例锁，也不共享 GriddyCode 的设置目录。

这台机器的既有 Windows 日志记录了两款软件在 `nvoglv64.dll` 中的驱动崩溃，不能把这种崩溃当成应用主动互斥。兼容启动器用于减少已知 RTSS 图层冲突；完整测试记录在项目 `qa` 目录。

Windows 10/11 64 位，需要能运行 Vulkan 的显卡与正常驱动。翻译和例句查询需要网络；主界面与设置不需要联网。

单词本查看、编辑和本地 Markdown 同步可离线使用；获取新译文、音标、例句和在线读音需要网络。iCloud 跨设备同步依赖其客户端与网络，失败通知后可从设置重新同步。
